### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

|**№**|**Требование**|
| 1 | Доступность сервисов не ниже 99,9%, бесперебойная работа 24/7 |
| 2 | Использование шифрования трафика и для сайта и для интернет-банка (TLS), механизм защиты персональных данных|
| 3 | В случае неполадок предусмотреть переключение на резервный ЦОД |
| 4 | Быстрый отклик на действия пользователя, целевые SLO для ключевых операций — сотни миллисекунд |
| 5 | Максимально использовать текущие технологии (базы данных MS SQL и Oracle) и компетенции; избегать доработок ядра интернет-банка подрядчиком, следить за совместимостью технологий |
| 6 | Внедрение и поддержка документирования решений | 
| 7 | Необходимо избегать прямой работы интернет-банка с API АБС в новом процессе |
| 8 | Учитывать ограничения систем: АБС может масштабироваться только вертикально из-за своей базы данных|
### <a name="_qmphm5d6rvi3"></a>**Решение**
1. Подключаем шифрование при передачи данных на сайте и в интернет-банке.
2. Чтобы дальше не перегружить АБС нужно будет добавить новый сервис, который будет отвечать за работу с заявками, ставками и депозитами. Добавить очередь для обмена сообщениями (Kafka).
### <a name="_bjrr7veeh80c"></a>**Альтернативы**
1. Можно обойтись без создания дополнительного сервиса для новых заявок, напрямую отправлять их в АБС. Но это увеличивает риск перегрузки АБС и ее доступность.

**Недостатки, ограничения, риски**

1. Сейчас процесс работы с заявками и депозитами происходит в ручном режиме - в будущем необходимо это автоматизировать
